# Requisition `paused_at` / `paused_reason` / `paused_by` — DDL Apply Instructions

**File:** `2026-08-28-mrf-pause.sql`
**Do not hand-edit `schema.prisma`** — per `docs/reference/VENDOR_PROCESS.md` §13, this repo always introspects the live DB.

## What this changes and why

Real MRF-level pause never shipped, despite being scoped in
`docs/HR-CANDIDATE-PIPELINE-FAQ-AND-GAP-PLAN-2026-08-26.md` (gap G1) alongside
candidate-level pause (Q33). What shipped 2026-08-26 was candidate-level pause
plus MRF manual closure (Q34) — including a closure reason named
`on_hold_indefinitely` that fully **closes** the requisition, not pauses it.
This adds a genuinely separate, reversible pause state.

## Steps to apply

1. Run the SQL against the database:
   ```
   psql "$DATABASE_URL" -f backend/prisma/ddl/2026-08-28-mrf-pause.sql
   ```
   Additive and idempotent — safe to re-run. No backfill needed; every existing
   row is correctly "not paused" (`paused_at IS NULL`) by default.

2. Stop the backend (and the queue worker — both hold the Prisma query
   engine), then re-introspect and regenerate:
   ```
   cd backend
   npx prisma db pull
   npx prisma generate
   ```

3. Restart the backend. Confirm `paused_at`, `paused_reason`, `paused_by`
   appear on the `rpa_mrf` model in `schema.prisma`.

## Rollback

The columns are additive and nothing reads them before the code change ships,
so rolling back the code is enough. To remove the columns entirely:

```sql
DROP INDEX IF EXISTS idx_rpa_mrf_unpaused;
ALTER TABLE rpa_mrf
  DROP COLUMN IF EXISTS paused_at,
  DROP COLUMN IF EXISTS paused_reason,
  DROP COLUMN IF EXISTS paused_by;
```
